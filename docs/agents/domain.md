# Domain docs

## Layout

This repository uses a single context:

- Glossary: `GLOSSARY.md` at the repository root.
- Architecture decision records: `docs/adr/`.

## Before exploring

Read the glossary and ADRs relevant to the area being explored.
If they do not exist, proceed silently.
The `/domain-modeling` skill creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
For an undefined concept, reconsider invented terminology or note the gap for `/domain-modeling`.

## Decision conflicts

Flag any proposal that conflicts with an existing ADR.
Name the conflicting ADR rather than silently overriding it.
